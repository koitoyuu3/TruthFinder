5.真值发现（迭代次数不同）（中间某一轮次，节点变成恶意的）
 score_shock_mean：这一轮里，方法对“来源可靠性分数”的平均跳变量。 
- 先对每个来源 website 算： score_shock = |score_this_round - score_prev_round| 然后对同一轮所有来源取平均。 所以它表示： “这一轮方法整体把各来源分数改动了多少”。 数值越大，说明该方法这轮内部权重/可靠性调整越剧烈。
- attack_induced_shock_mean 这是最关键的列，表示“攻击额外带来的 shock”。 它不是直接等于 score_shock_mean，而是把攻击轨道和干净轨道做差： attack_induced_shock = max(0, score_shock_mean_attacked - score_shock_mean_clean)
  - 也就是说，它衡量的是： “相比正常情况下这一轮本来就会有的分数波动，攻击又额外造成了多少波动”。 数值越小越好，表示方法更稳、更抗攻击。

  method：方法名，比如 EnhancedTruthFinder-Hybrid、SenteTruthFinder
 - run_count：这个方法总共跑了多少次 benchmark 子任务
 - success_count：成功完成的 run 数量，success=True 的个数
 - overall_mean_elapsed_sec：该方法所有 run 的平均执行耗时，单位秒；来自每次 worker 返回的 elapsed_sec
 - overall_mean_peak_delta_rss_mb：平均峰值增量内存，单位 MB；等于运行期间 peak_rss_mb - baseline_rss_mb 的均值
 - overall_mean_source_score_pct：平均“质量分”，是各 run 的 mean_source_score_pct 再取均值；它先把方法原生 source_scores 转成百分制后，再对网站分数求平均，见 decentralized_truth_discovery/examples/
   agent_scalability_benchmark.py:343
 - overall_mean_composite_score：平均综合分；越大越好。单次综合分公式是
   time_weight * latency_score + memory_weight * memory_score + quality_weight * quality_score
   其中三个 score 都先被归一化到 0–100，见 decentralized_truth_discovery/examples/agent_scalability_benchmark.py:398 和 decentralized_truth_discovery/examples/agent_scalability_benchmark.py:402
