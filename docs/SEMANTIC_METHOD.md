# SemanticTruth: 面向混合数据的跨批次鲁棒真值发现方法

## 1. 引言

在去中心化预言机系统中，多个外部数据源（source）对同一批数据对象（object）提供输入，系统需要从中提取可信的真值，同时对抗可能存在的拜占庭（Byzantine）恶意源。现有方法在此问题上各有侧重：

- **BasicTruth**（原始 TruthFinder [Yin et al., 2008]）：每个源对若干对象提供文本 fact，系统将每条 fact 视为一个待评估的"声明"。算法在"源可信度"和"声明置信度"之间交替迭代直到收敛：首先，每条声明的置信度等于提供该声明的所有源的可信度之和（越多高可信度源支持，声明越可信）；然后，每个源的可信度更新为其所有声明的平均置信度（提供的声明越可信，源越可信）。为了处理语义上相近但表述不同的声明，BasicTruth 引入了**隐含关联函数（implication）**：如果声明 $f_2$ 与 $f_1$ 语义相近（通过 TF-IDF 余弦相似度衡量），那么 $f_2$ 的置信度会通过一个加权的传播机制"流"向 $f_1$，具体地，$f_1$ 的置信度会加上一个与 $f_2$ 的置信度和两者相似度成正比的增量。这使得含义相同但表述不同的声明能够互相增强。最终收敛后，每个对象下置信度最高的声明被选为真值。BasicTruth 的局限在于：它不区分数值与文本数据（将所有输入统一用文本相似度处理），也没有专门的异常源检测机制——恶意源只能通过其声明与多数声明不一致而被间接降权，但无法在跨批次间累积恶意源的历史记录。

- **DecentTruth** [Xiao et al., 2023]：面向去中心化预言机的连续数值场景（如代币价格、股票报价）。每个 epoch（批次），系统处理一批数据对象，每个源对每个对象报告一个数值。真值估计采用**加权平均**：每个对象的估计真值等于所有源报告值按各自可信度加权的均值。在可信度方面，DecentTruth 为每个源维护两个指标——**误差 $\epsilon_s$**（源报告值与估计真值之间的均方误差，越小说明源报告越准确）和**一致性 $\kappa_s$**（衡量源的误差是否在相邻 epoch 间剧烈波动）。一致性的计算使用互补误差函数 erfc：$\kappa_s = \text{erfc}(\beta|\epsilon_s - \hat{\epsilon}_s|) \cdot (1-\alpha) + \hat{\kappa}_s \cdot \alpha$，其中 $\hat{\epsilon}_s, \hat{\kappa}_s$ 是上一个 epoch 的值，$\alpha$ 控制历史衰减。erfc 是一个从 1 单调递减到 0 的函数——当源的误差在两个 epoch 之间几乎不变时（说明它一直在正常报告），erfc 输出接近 1，一致性高；当误差突然跳变时（可能被拜占庭攻击），erfc 输出接近 0，一致性骤降。最终源的可信度为 $r_s = \kappa_s / \epsilon_s$：一致性高且误差小的源获得高可信度。DecentTruth 的局限在于它完全不处理文本数据，且使用加权平均（而非加权中位数或鲁棒统计）估计真值，当恶意源报告极端值时容易被拉偏。

- **SenteTruth** [Zeng et al., 2025]：面向 LLM 生成的文本数据场景。多个预言机节点对同一问题调用 LLM 获取回答，由于 LLM 的生成随机性，不同节点获得的文本可能在语义上相近但表述不同，甚至部分恶意节点可能返回完全错误的回答。SenteTruth 用 SBERT（Sentence-BERT）将每条文本编码为语义向量，通过余弦相似度衡量文本间的语义相关性。对每条文本 $i$，计算它与所有其他文本的平均余弦相似度 $\phi(v_i)$——如果一条文本和大多数文本语义接近，$\phi$ 值高；如果是恶意节点提供的无关文本，$\phi$ 值低。真值选择为 $\hat{\mathcal{D}} = \arg\max_i C_i \cdot \phi(v_i)$，即选择"节点可信度 $\times$ 语义相关度"乘积最高的文本。可信度更新公式为 $C_i \leftarrow \frac{\sum C_j}{\sum C_j \cdot \phi(v_j)} \cdot C_i \cdot \phi(v_i)$：如果节点提供的文本与多数文本一致（$\phi$ 高），其可信度上升；否则下降。SenteTruth 的局限在于它**完全不利用文本中嵌入的数值信息**——如果恶意源仅篡改文本中的关键数字（如将"目标价 166 美元"改为"目标价 101 美元"），由于语义向量对数字变化不敏感（两句话的 SBERT 余弦相似度可高达 0.97），SenteTruth 无法识别这种攻击。

- **SenFeedTruth** [Zeng et al., 2025]：面向 IoT 传感器流数据（如温度、湿度、电压等连续更新的数值），其核心是**复合真值发现算法 CompositeTD**，将两种经典真值发现范式——迭代式和增量式——融合成一个自适应切换框架，在准确性和实时性之间取得平衡。

  **迭代式真值发现**：在每个时间戳 $t$，对所有对象的真值和所有源的权重进行交替迭代直到收敛。具体地，固定源权重时，每个对象的真值用加权平均估计：$\hat{v}_o^t = \frac{\sum_{s} w_{u,s}^t v_{s,o}^t}{\sum_{s} w_{u,s}^t}$（源权重越高的源，其报告值对真值的贡献越大）；固定真值时，每个源的权重按其总误差的单调递减函数更新：$w_{u,s} = f(\sum_o d(v_{s,o}, \hat{v}_o))$（源报告值与估计真值的距离越大，权重越低）。两步交替执行直到权重和真值都不再变化。迭代式方法准确但计算量大，每个时间戳都需要多轮迭代才能收敛，无法满足传感器流数据的实时要求。

  **增量式真值发现**：不做迭代，直接用上一个时间戳的源权重 $W^{t-1}$ 来计算当前时间戳的真值 $\hat{V}^t$——只需一次加权平均即可完成，计算效率极高。但它的缺点是"假设源的行为不会突变"：如果某个源突然被拜占庭攻击控制开始报告错误值，增量式方法无法及时调整权重，误差会逐步累积并扩散到后续时间戳。

  **CompositeTD 的自适应切换机制**：CompositeTD 的核心思想是"平时用增量式保证实时性，检测到异常时切换为迭代式保证准确性"。具体地，系统持续监控每个源的**权重演变量** $\Delta w_{u,s}^t = |w_{u,s}^t - w_{u,s}^{t-1}|$——即源权重在相邻时间戳之间的变化幅度。当所有源的权重变化都很小时（$\Delta w_{u,s}^t \leq \frac{\sqrt{\varepsilon}}{|S|}$，其中 $\varepsilon$ 是误差阈值，$|S|$ 是源数量），说明数据分布稳定，无源异常，继续使用增量式；一旦某个源的权重变化超过该阈值——例如一个此前正常的源突然被拜占庭控制后开始报告偏差值，其权重在增量更新中会发生明显跳变——系统立即切换为迭代式，交替执行真值估计和权重估计直到重新收敛。收敛后系统再切回增量式。

  **MAP 估计更新源权重**：CompositeTD 用**最大后验（MAP）估计**而非简单的启发式规则来更新源权重。它假设每个源的监控误差 $\Delta v_{s,o}^t = \sqrt{d(v_{s,o}^t, \hat{v}_o^t)}$ 服从均值为 0、方差与 $w_{u,s}^t$ 成反比的正态分布，并为源权重施加 **Gamma 先验** $w_{u,s}^t \sim \Gamma(\alpha, \beta)$。通过最大化后验概率，得到权重的闭式解：$w_{u,s}^T = \frac{-2+2\alpha + \sum_{t=1}^T \sum_o \mathbb{1}_{s,o}}{2\beta + \gamma \cdot \prod_{t=1}^T \sum_o (\Delta v_{s,o}^t)^2}$。直观含义是：分子反映源参与数据报告的历史"经验量"（加上先验），分母反映源的历史累积误差（加上先验正则项）——参与越多且误差越小的源获得越高的权重。Gamma 先验起到正则化作用，防止权重在早期数据量较少时剧烈波动。

  **历史平滑**：CompositeTD 还将历史真值 $\hat{v}_o^{t-1}$ 视为一个"虚拟数据源"，以固定权重 $\tilde{w}$ 参与当前时间戳的加权平均：$\hat{v}_o^t = \frac{\sum_s w_{u,s}^t v_{s,o}^t + \tilde{w} \hat{v}_o^{t-1}}{\sum_s w_{u,s}^t + \tilde{w}}$。这使得真值估计具有时间连续性，避免在传感器数据自然波动时产生过大的真值跳变。

  SenFeedTruth 的局限在于它**完全面向数值型传感器数据，不处理文本**；且真值估计仍基于加权平均（非鲁棒统计），对极端离群值的抵抗力有限。

**SemanticTruth** 的设计目标是统一处理数值数据和文本数据，并在两个通道之间建立交叉验证机制。其核心特点包括：

1. **双通道架构**：系统将输入数据分为数值和文本两个独立通道分别处理。数值通道不使用简单的加权平均，而是采用鲁棒统计方法（IRLS + Tukey bisquare）——它以加权中位数为起点，通过迭代地给偏离中心的值分配更低的权重，使得即使存在极端离群值，估计出的真值也不会被拉偏。文本通道使用"语义+数值双信号软投票"：在比较两条文本的相似程度时，不仅看它们的语义是否相近（通过 SBERT 向量的余弦相似度），还检查它们包含的数字是否一致（通过高斯衰减评分），两个信号各占一半权重，综合后进行加权投票选出最可信的文本。这样，即使恶意文本在语义上与真实文本高度相似，只要篡改了关键数字，数值信号就会将其拉低。

2. **跨批次可信度学习**：系统不是在每个批次内从头评估源的可信度，而是通过 Beta-Bernoulli 共轭先验在多个批次间累积每个源的历史表现。每个源维护两个计数器（$\alpha$ 记录"表现好"的累积量，$\beta$ 记录"表现差"的累积量），可信度就是 $\alpha / (\alpha + \beta)$。每处理一个批次，根据源在该批次中与真值的一致程度，分别给 $\alpha$ 或 $\beta$ 加一点。随着批次的积累，一个长期表现良好的源会积累大量的 $\alpha$，偶尔一次表现不佳不会显著拉低其可信度（"信任惯性"）；而一个持续偏离的恶意源则会逐渐积累 $\beta$，可信度被压到接近 0 后被门控机制排除在外。

3. **统一的数值处理**：文本通道中嵌入的数值信息使用与数值通道完全一致的评分机制——都是高斯衰减函数（值越接近参考值得分越高，偏离越远得分指数衰减趋近 0），且使用相同的自适应 scale 计算方式（取 MAD 鲁棒估计和标准差中较大者作为衰减的尺度参数）。这保证了系统在数值处理上的方法论一致性：无论一个数字出现在纯数值字段中还是嵌入在一段文本里，它都会以相同的标准被评估。

## 2. 问题形式化

### 2.1 系统模型

考虑一组数据源 $\mathcal{S} = \{s_1, s_2, \dots, s_S\}$，以 epoch（批次）为单位处理数据。每个 epoch $e$ 包含一批数据对象 $\mathcal{B}_e$。每个源 $s$ 对对象 $o \in \mathcal{B}_e$ 可能提供两类输入：

- **数值输入** $x_{s,o} \in \mathbb{R}$：如币价
- **文本输入** $t_{s,o} \in \Sigma^*$：如新闻摘要、天气情况

系统的目标是为每个对象 $o$ 估计真值 $\hat{x}_o$（数值）或 $\hat{t}_o$（文本），并为每个源 $s$ 维护可信度 $r_s \in [0, 1]$。

### 2.2 威胁模型

恶意源可以在任意时刻提供任意偏离真值的输入。恶意源可能进行**协同攻击**（collude）：多个恶意源报告相同的虚假值，试图形成"多数"假象。系统假设诚实源始终占多数。

## 3. 源可信度管理

### 3.1 Beta-Bernoulli 共轭先验

SemanticTruth 使用 Beta 分布的共轭先验来跟踪每个源的可信度。每个源 $s$ 维护两个参数 $(\alpha_s, \beta_s)$，初始值均为 $(\alpha_0, \beta_0) = (1, 1)$，对应均匀先验（无偏初始信念）。

**可信度计算：**

$$r_s = \frac{\alpha_s}{\alpha_s + \beta_s}$$

**为什么选择 Beta-Bernoulli 而非其他可信度表示？** 现有方法的可信度机制各有不足：BasicTruth 的 $\tau_s$ 是每轮从头迭代收敛的结果，没有跨批次记忆，无法利用历史信息识别长期恶意源；DecentTruth 的 $r_s = \kappa_s/\epsilon_s$ 是无界的（$\epsilon_s$ 趋近 0 时 $r_s$ 可以任意大），需要额外归一化，且 EMA 指数衰减意味着早期的历史表现会被快速遗忘；SenteTruth 的 $C_i$ 是乘法更新的无界标量，跨批次保留时可能无限增长或趋近零，缺乏稳定性；SenFeedTruth 的 Gamma 先验 MAP 估计虽然也是贝叶斯框架，但其权重 $w_s$ 同样无上界，且 MAP 估计涉及历史误差的累乘，数值上可能不稳定。Beta-Bernoulli 被选中的原因是它同时满足三个需求：**有界**（$r_s$ 天然在 $[0,1]$ 内，可直接用作投票权重，无需归一化或截断）、**有记忆**（$\alpha + \beta$ 的累积量编码了"见过多少证据"，证据越多单次异常的冲击越小）、**可解释**（$\alpha$ 是"表现好的累积次数"，$\beta$ 是"表现差的累积次数"，$r_s$ 就是"好的比例"的贝叶斯估计）。

**与其他方法的对比：**

| 方法 | 可信度表示 | 更新方式 |
|------|-----------|---------|
| BasicTruth | $\tau_s =$ fact 置信度均值 | 迭代收敛直到全局稳定 |
| DecentTruth | $r_s = \kappa_s / \epsilon_s$ | erfc 一致性 / 均方误差 |
| SenteTruth | $C_i$ 标量 | $C_i \leftarrow \frac{\sum C_j}{\sum C_j \phi(v_j)} \cdot C_i \cdot \phi(v_i)$ |
| SenFeedTruth | $w_s$ 源权重 | MAP 估计（Gamma 先验） |
| **SemanticTruth** | $(\alpha_s, \beta_s)$ Beta 参数 | $\alpha_s \mathrel{+}= \eta \cdot c_s$，$\beta_s \mathrel{+}= \eta \cdot (1 - c_s)$ |

其中 $c_s \in [0, 1]$ 为该批次中源 $s$ 的一致性得分（consistency score），$\eta$ 为学习率（默认 1.0）。

**为什么初始值取 $(\alpha_0, \beta_0) = (1, 1)$？** 在贝叶斯框架中，$(1,1)$ 对应均匀先验——即在没有任何历史数据时，系统对每个源"是好是坏"完全无偏（$r_s = 0.5$）。如果取 $(\alpha_0, \beta_0) > (1,1)$（例如 $(2,2)$），则初始惯性更大，系统需要更多批次才能区分好坏源，前期对恶意源的容忍度更高；如果取 $(\alpha_0, \beta_0) < (1,1)$（例如 $(0.5, 0.5)$，Jeffreys 先验），则先验在 0 和 1 附近有峰值，少量证据就会推动可信度走向极端，可能导致误判。$(1,1)$ 在"快速响应"和"稳定性"之间取得平衡。

**为什么 $\eta$ 默认取 1.0？** $\eta$ 控制每个批次的证据对可信度的影响幅度。$\eta = 1.0$ 意味着每个批次贡献 1 个"观测单位"——经过 $n$ 个批次后 $\alpha + \beta = 2 + n$，此时单个批次对可信度的最大影响约为 $1/(\alpha+\beta) \approx 1/(2+n)$。这提供了一个合理的学习速度：前几个批次（$n$ 小）变化较大，系统快速建立对源的初步判断；后续批次（$n$ 大）变化趋缓，可信度逐渐稳定。若 $\eta$ 过大（如 5.0），前几个批次可能因噪声导致可信度剧烈波动；若 $\eta$ 过小（如 0.1），需要数十个批次才能区分恶意源和诚实源。

### 3.2 跨通道可信度更新

每个 epoch 结束后，两个通道分别产出各自的 consistency score：

- 数值通道：$c_s^{\text{num}}$
- 文本通道：$c_s^{\text{txt}}$

最终更新使用两通道的均值（如源仅出现在一个通道中，则使用该通道的值）：

$$c_s = \text{mean}\big(\{c_s^{\text{num}}, c_s^{\text{txt}}\} \cap \text{available}\big)$$

$$\alpha_s \leftarrow \alpha_s + \eta \cdot c_s, \quad \beta_s \leftarrow \beta_s + \eta \cdot (1 - c_s)$$

**为什么用均值而非取最小值或加权组合？** 取均值的设计意图是让两个通道对可信度的贡献对等——一个源在数值通道表现优秀但在文本通道表现一般，其综合可信度应为中等，而非被最差的通道一票否决。如果取最小值（$\min$），则任一通道的低分都会严重拉低整体可信度，对仅参与一种数据类型的源不公平（例如一个只报告数值的源在文本通道没有得分，取 $\min$ 会直接得 0）。如果按数据量加权，则大量低质量数据的通道可能主导评分。均值是最简洁且对称的选择。当源仅出现在一个通道时退化为该通道的值，避免了缺失通道的惩罚。

**为什么更新后的可信度在下一个 epoch 才生效？** 这是为了避免循环依赖：当前 epoch 的真值估计和一致性评分依赖于源的可信度权重；如果在同一个 epoch 内根据评分结果立即更新可信度并重新估计真值，就形成了"真值→评分→可信度→真值"的反馈环，可能导致不稳定或需要额外的内层迭代来收敛。延迟一个 epoch 生效使得每个 epoch 的计算是单向的（读取可信度→估计真值→计算评分→更新可信度），流程简洁、确定性强，且与 DecentTruth 和 SenFeedTruth 的逐批次更新模式一致。

## 4. 数值通道

### 4.1 概述

数值通道处理 $x_{s,o} \in \mathbb{R}$ 类型的输入。其目标是对每个对象 $o$ 估计一个鲁棒的真值 $\hat{x}_o$，并为每个源计算一致性得分。

### 4.2 可信度门控预过滤

在真值估计开始前，先排除历史可信度显著低于群体均值的源：

$$\text{gate} = \bar{r} \cdot \lambda_{\text{gate}}$$

其中 $\bar{r}$ 为当前参与源的平均可信度，$\lambda_{\text{gate}} = 0.3$ 为门控比例。仅保留 $r_s \geq \text{gate}$ 的源参与后续的 IRLS 估计。

**为什么要做预过滤而不是完全依赖 IRLS 的鲁棒降权？** IRLS + Tukey bisquare 虽然能在 batch 内降低离群值的权重，但它基于统计假设（多数值聚集在真值附近、离群值稀疏），当恶意源比例较高（如 30%-40%）时，恶意源可能协同报告一个偏离值，形成虚假的"聚集中心"，误导 IRLS 的初始中位数和 MAD 估计。预过滤利用跨批次累积的可信度信息，在 IRLS 开始前就将已被识别的恶意源排除，降低恶意源在 batch 内的有效比例，从而保证 IRLS 的统计假设仍然成立。换言之，预过滤和 IRLS 是**两层防线**：预过滤利用"历史证据"排除已知恶意源，IRLS 利用"当前 batch 统计特征"处理尚未被识别的轻度异常。

**为什么使用相对门控（基于平均可信度）而非绝对阈值？** 使用相对门控 $\text{gate} = \bar{r} \cdot \lambda_{\text{gate}}$ 而非固定阈值（如 $r_s < 0.3$），是因为所有源的可信度水平会随 epoch 推进而整体变化。在前几个 epoch 中，所有源的 $r_s$ 都接近 0.5（初始值），绝对阈值 0.3 不会过滤任何源；但在后期，如果所有诚实源的 $r_s$ 都上升到 0.9 以上，而恶意源降到 0.4，此时绝对阈值 0.3 仍然不会过滤恶意源。相对门控会随群体水平自适应调整：群体 $\bar{r} = 0.85$ 时门控为 $0.85 \times 0.3 = 0.255$，足以过滤 $r_s = 0.4$ 的源并不明显；但如果 $\bar{r} = 0.9$，门控为 0.27，而 $r_s = 0.15$ 的恶意源会被排除。关键在于相对门控始终以"显著低于群体平均"作为过滤标准，不受可信度的绝对尺度影响。

**为什么 $\lambda_{\text{gate}} = 0.3$？** 这是一个保守的设置：$\lambda_{\text{gate}} = 0.3$ 意味着只有可信度低于群体平均值的 30% 的源才会被过滤。例如群体平均 $\bar{r} = 0.7$ 时，门控为 0.21，只有可信度极低的源才会被排除。选择保守阈值是因为过早或过激地排除源可能误伤因噪声导致暂时低分的诚实源——一旦诚实源被排除，后续批次中诚实源比例下降，恶意源反而占比上升，可能造成级联恶化。$\lambda_{\text{gate}} = 0.3$ 确保只有经过多个批次证据累积、可信度已大幅落后于群体的源才会被排除。

**为什么使用硬截断而非进一步的软降权？** 源的可信度 $r_s$ 本身已经在 IRLS 中作为基础权重 $w_i^{\text{base}}$ 参与软降权——可信度低的源已经获得更低的权重。门控的作用是在可信度**极低**时直接排除，而非仅仅降权。这是因为即使权重很低，恶意源的极端值在加权平均/中位数中仍可能产生微弱偏移；当恶意源数量多时，这些微弱偏移会累积。硬截断彻底消除了这些源的影响。

**与 DecentTruth 的对比**：DecentTruth 不做预过滤，而是通过 $\kappa_s$ 接近 0 使恶意源的 $r_s \approx 0$，间接降低其影响。SemanticTruth 的门控是显式的硬截断，在恶意源比例较高时更有效。

### 4.3 IRLS + Tukey Bisquare 真值估计

对通过门控的源集合 $\{(x_i, w_i)\}_{i=1}^n$（值和权重），执行迭代重加权最小二乘（IRLS）。

**权重 $w_i$ 的来源：** 这里的 $w_i$ 即为源 $s_i$ 的可信度 $r_{s_i}$，由 Section 3.1 中的 Beta-Bernoulli 共轭先验计算得到：

$$w_i = r_{s_i} = \frac{\alpha_{s_i}}{\alpha_{s_i} + \beta_{s_i}}$$

其中 $\alpha_{s_i}$ 和 $\beta_{s_i}$ 是源 $s_i$ 在历史批次中累积的 Beta 分布参数（初始值均为 1.0）。经过 Section 4.2 的门控预过滤后，仅保留 $r_{s_i} \geq \bar{r} \cdot \lambda_{\text{gate}}$ 的源进入 IRLS，因此这里的 $n$ 是通过门控的源数量。在 IRLS 的迭代过程中，$w_i$ 作为**基础权重**（后续步骤 4 中记为 $w_i^{\text{base}}$）保持不变，反映的是源的历史可信程度；而 Tukey bisquare 在每轮迭代中基于当前残差动态计算的 $w_i^{\text{Tukey}}$ 反映的是源在当前 batch 内的统计一致性。两者在步骤 4 中通过乘积组合，形成"历史可信度 $\times$ 当前一致性"的双重权重。

**步骤 1：加权中位数**

$$m = \text{WeightedMedian}(\{x_i\}, \{w_i\})$$

加权中位数满足 $\arg\min_m \sum_i w_i |x_i - m|$，实现为排序后在累积权重达到总权重 50% 处取值。

**为什么用加权中位数而非加权平均作为 IRLS 的初始估计？** IRLS 是一个迭代过程，初始估计的质量直接影响收敛速度和最终结果。加权平均的崩溃点（breakdown point）为 0——只需一个无穷大的离群值就能将均值拉到任意位置；加权中位数的崩溃点接近 50%——需要超过一半的数据被污染才会失效。在恶意源可能报告极端值的场景下，加权中位数提供一个远比加权平均可靠的起点，使后续的 Tukey bisquare 迭代能从正确的"聚集中心"开始，而不是从被离群值拉偏的位置开始。DecentTruth 使用加权平均 $\hat{x}_o = \frac{\sum r_s x_{s,o}}{\sum r_s}$（Eq. 3, 9），当恶意源报告极端值时容易被拉偏。

**步骤 2：MAD 尺度估计**

$$\text{MAD} = \text{median}(|x_i - m|)$$

$$\sigma = 1.4826 \times \text{MAD}$$

**为什么用 MAD 而非标准差（std）来估计尺度？** 标准差使用平方和计算，一个极端离群值就能使 std 剧增（例如 9 个源报 100、1 个恶意源报 10000，std ≈ 3000，远偏离真实分散度）。MAD 使用绝对偏差的中位数，与中位数一样具有接近 50% 的崩溃点——同一场景下 MAD ≈ 0，正确反映了多数源高度一致的事实。因子 1.4826 是高斯分布下 MAD 与标准差的换算系数（$\sigma = 1.4826 \times \text{MAD}$），使 $\sigma$ 成为鲁棒的"标准差"估计——在数据确实服从高斯分布时，MAD × 1.4826 与标准差一致；在有离群值时，它不受污染。

**步骤 3：Tukey Bisquare 权重**

$$u_i = \frac{x_i - m}{c \cdot \sigma}, \quad w_i^{\text{Tukey}} = \begin{cases} (1 - u_i^2)^2 & \text{if } |u_i| \leq 1 \\ 0 & \text{if } |u_i| > 1 \end{cases}$$

**为什么选择 Tukey bisquare 而非其他鲁棒权重函数（如 Huber）？** 常见的鲁棒权重函数有两类：Huber 函数对离群值给予固定但非零的权重（即"软"降权，永远不会完全忽略离群值）；Tukey bisquare 在偏离超过阈值 $c \cdot \sigma$ 后直接赋权为 0（即"硬"截断，完全忽略远离群值）。在预言机场景中，恶意源可能报告任意极端值，这些值不携带任何关于真值的信息。Huber 函数会给这些极端值保留小但非零的权重，在恶意源较多时这些残余权重累积仍会产生偏移；Tukey bisquare 将它们完全排除，更适合"恶意值完全不可信"的假设。

参数 $c = 4.685$（默认），这是经典鲁棒统计中的标准取值，在高斯噪声下保留 95% 的渐近效率。**为什么取 4.685？** $c$ 控制"正常值"和"离群值"的边界：$c$ 越小，越多的值被视为离群值而被排除，鲁棒性更强但效率降低（丢弃了有用信息）；$c$ 越大，越接近普通最小二乘，效率高但鲁棒性弱。$c = 4.685$ 是鲁棒统计领域公认的平衡点，它保证在数据确实服从高斯分布（无离群值）时，Tukey bisquare 估计器的渐近效率为标准最小二乘的 95%——即几乎不损失精度；同时对离群值仍有强截断能力。

**设计分工说明**：Tukey bisquare 的职责是提供 batch 内的鲁棒估计，处理自然噪声和轻度异常值；**拜占庭恶意源的识别与过滤由跨 batch 的 Beta-Bernoulli 可靠度追踪（Section 3）和可信度门控（Section 4.2）承担**。两层机制各司其职：IRLS 在单个 batch 内温和降权，可靠度追踪在多个 batch 间累积证据后将恶意源彻底排除。**为什么需要两层而非只用一层？** 单靠 Tukey bisquare 无法解决"恶意源协同攻击"：当多个恶意源报告相同的偏离值时，它们在统计上形成"另一个聚集中心"，Tukey 可能将其视为正常值而非离群值。跨 batch 的可信度追踪通过多轮证据累积识别出这些协同恶意源，门控将其排除后，Tukey 只需处理剩余的诚实源中的自然噪声，统计假设重新成立。反过来，单靠门控也不够——在前几个 epoch 可信度尚未分化时，门控不生效，此时需要 Tukey 在 batch 内提供鲁棒性。

**步骤 4：更新真值估计**

$$\hat{x}_o = \frac{\sum_i w_i^{\text{base}} \cdot w_i^{\text{Tukey}} \cdot x_i}{\sum_i w_i^{\text{base}} \cdot w_i^{\text{Tukey}}}$$

其中 $w_i^{\text{base}}$ 为源可信度权重，$w_i^{\text{Tukey}}$ 为 Tukey 鲁棒权重。两者相乘，形成**双重过滤**：历史不可靠的源（低 $w^{\text{base}}$）和当前偏离的源（低 $w^{\text{Tukey}}$）同时被抑制。**为什么用乘积而非求和或取最小值？** 乘积使得两个信号的抑制效果**叠加**而非互相替代：一个历史可信度为 0.1 的源即使当前值恰好接近中位数（$w^{\text{Tukey}} = 1$），最终权重仍只有 0.1；一个历史可信度为 0.9 但当前值严重偏离的源（$w^{\text{Tukey}} = 0$），最终权重为 0。若用求和，两个信号可以互相补偿（如低 $w^{\text{base}}$ + 高 $w^{\text{Tukey}}$ 可能得到中等权重），削弱了各自的过滤效果；若用 $\min$，则浪费了另一个信号提供的细粒度信息。乘积是两个独立证据源的自然组合方式。

**步骤 5：收敛判断**

若 $|\hat{x}_o^{(t)} - \hat{x}_o^{(t-1)}| < \epsilon_{\text{tol}}$（默认 $10^{-8}$），则停止迭代。最多执行 $T_{\text{max}} = 10$ 轮。**为什么 $T_{\text{max}} = 10$？** IRLS 在实践中通常在 3-5 轮内收敛（权重和中心的相互调整很快稳定）。$T_{\text{max}} = 10$ 提供足够的余量以应对边界情况（如数据高度分散时收敛较慢），同时防止极端病态数据导致的无限循环。

**特殊情况**：若 $\sigma \leq \epsilon_{\text{tol}}$（即 MAD ≈ 0，说明多数源报告相同值），直接返回加权中位数 $m$。**为什么需要这个特殊处理？** 当多数源报告完全相同的值时，MAD = 0 导致 $\sigma = 0$。此时 Tukey bisquare 的标准化步骤 $u_i = (x_i - m)/(c \cdot \sigma)$ 出现除零，无法计算权重。直接返回中位数是最合理的选择——多数源已经一致同意该值，没有进一步优化的必要。

### 4.4 一致性评分

真值估计完成后，对**所有源**（包括被门控排除的）计算一致性得分：

**为什么对所有源（包括被门控排除的）都计算一致性得分？** 门控排除的目的是防止低可信度源污染真值估计，但不意味着放弃对这些源的持续评估。如果一个被门控排除的源在后续批次中开始报告正确值（例如故障恢复），它的一致性得分会上升，可信度 $r_s$ 会逐渐回升，最终重新通过门控。如果只对参与估计的源计算一致性，被排除的源将永远无法恢复——这对于暂时故障（非永久恶意）的源不公平，也降低了系统的源利用率。

$$\text{residual}_i = x_i - \hat{x}_o$$

$$\text{scale} = \max\big(1.4826 \times \text{MAD}(\text{residuals}),\; \text{std}(\text{residuals}),\; \epsilon_{\text{tol}}\big)$$

**为什么 scale 取三者的最大值？** 三个候选值各应对一种极端情况：（1）$1.4826 \times \text{MAD}$ 是鲁棒的尺度估计，在有离群值时不受污染，是默认首选；（2）$\text{std}$ 在所有值都是诚实但分散度较大的情况下可能比 MAD 更合适——例如 MAD 恰好为 0（多数源报告相同值但个别诚实源因噪声略有偏差），此时 MAD 为 0 会导致所有偏离源的一致性得分都为 0，过于严苛，而 std 能提供更宽松的尺度；（3）$\epsilon_{\text{tol}}$ 是最后的数值安全兜底——当所有源报告完全相同的值时 MAD = std = 0，取 $\epsilon_{\text{tol}}$ 避免除零。取最大值确保 scale 永远不会过小，防止一致性评分因尺度过小而过度惩罚微小偏差。

$$c_i^{\text{num}} = \exp\!\Big(-\frac{1}{2}\Big(\frac{\text{residual}_i}{\text{scale}}\Big)^2\Big)$$

**为什么使用高斯衰减函数而非其他衰减形式（如线性衰减或阶跃函数）？** 高斯衰减 $\exp(-\frac{1}{2}(r/s)^2)$ 具有几个理想性质：（1）在 $r = 0$（完全一致）时得分为 1.0，在 $r \to \infty$ 时得分趋近 0，是平滑的单调递减函数；（2）对小偏差容忍——偏离 1 个 scale 时得分约 0.607，偏离 2 个 scale 时得分约 0.135——诚实源的自然噪声通常在 1-2 个 scale 内，不会被过度惩罚；（3）对大偏差急剧衰减——偏离 3 个 scale 以上时得分低于 0.011，恶意值被几乎完全压制。线性衰减 $\max(1-r/s, 0)$ 对小偏差同样惩罚一个固定斜率，不够平滑且需要人为设定截断点；阶跃函数（在/不在某个范围内）则失去了梯度信息，无法区分"略微偏离"和"严重偏离"。高斯衰减在连续性、灵敏度分布上是自然的选择。

**与 DecentTruth 的对比**：DecentTruth 使用 $\kappa_s = \text{erfc}(\beta|\epsilon_s - \hat{\epsilon}_s|) \cdot (1-\alpha) + \hat{\kappa}_s \cdot \alpha$（Eq. 5），其中 $\text{erfc}$ 也是单调递减函数，但它检测的是**误差的变化量**（相邻 epoch 之间），而非绝对偏差。SemanticTruth 的高斯衰减检测的是**当前值与真值的绝对偏差**。两者互补：DecentTruth 更擅长检测"突然变坏"的源，SemanticTruth 更擅长检测"一直偏离"的源。

**与 SenFeedTruth 的对比**：SenFeedTruth 使用 MAP 估计更新权重（Eq. 6），当 $\Delta w_{s} > \sqrt{\epsilon}/|S|$ 时触发迭代重新收敛。这是一种"变化检测"机制，与 SemanticTruth 的逐 epoch 高斯评分在目标上类似，但实现方式不同。

## 5. 文本通道

### 5.1 概述

文本通道处理 $t_{s,o} \in \Sigma^*$ 类型的输入。与数值通道不同，文本没有自然的算术运算（如求均值），因此真值选择采用"选出最佳文本"而非"计算数值"。

SemanticTruth 的文本通道同时利用**语义信号**（通过嵌入向量的余弦相似度）和**数值信号**（从文本中提取的数字），形成双信号验证机制。这是与 SenteTruth（纯语义）的关键区别。

### 5.2 文本编码

每条文本 $t_i$ 被编码为向量 $\mathbf{v}_i$：

$$\mathbf{v}_i = \text{Normalize}(\text{SBERT}(t_i))$$

其中 SBERT（Sentence-BERT）为多语言预训练模型（默认 `paraphrase-multilingual-MiniLM-L12-v2`），$\text{Normalize}$ 为 L2 归一化。归一化后向量的内积即为余弦相似度。

**为什么用 SBERT 而非 TF-IDF 或其他编码方式？** BasicTruth 使用 TF-IDF 余弦相似度作为 implication 函数，但 TF-IDF 是基于词袋的稀疏表示，无法捕捉语义等价性——"全球变暖加剧"和"气候变化恶化"在 TF-IDF 下几乎没有重叠词，相似度接近 0，但语义上它们表达相同含义。SBERT 将句子映射到稠密语义空间，语义相近的句子即使用词完全不同也会有高余弦相似度，这对于预言机场景至关重要：不同源对同一事件的描述可能用词差异很大（不同语言、不同措辞），但语义应该一致。选择 `paraphrase-multilingual-MiniLM-L12-v2` 模型是因为它专为多语言释义检测训练，模型体积小（约 120MB），推理快，适合预言机节点的计算约束。

**为什么做 L2 归一化？** 归一化后，向量内积 $\mathbf{v}_i^\top \mathbf{v}_j$ 直接等于余弦相似度 $\cos(\mathbf{v}_i, \mathbf{v}_j)$，省去了后续每次计算相似度时的归一化开销。同时，归一化使所有向量位于单位超球面上，消除了不同文本长度导致的向量模长差异——否则长文本可能因嵌入向量模长较大而在内积计算中获得不合理的优势。

**与 SenteTruth 的对比**：SenteTruth 同样使用 SBERT 编码（Eq. 1），两者在编码步骤上完全一致。

### 5.3 数值提取

从每条文本中使用正则表达式提取所有数值：

$$\text{nums}(t_i) = \text{regex\_findall}(\texttt{-?\textbackslash d+(?:\textbackslash.\textbackslash d+)?},\; t_i)$$

例如，`"目标价为166.32美元，上涨29.29%"` $\rightarrow$ $[166.32, 29.29]$。

**为什么用正则表达式而非 NLP 命名实体识别（NER）来提取数值？** NER 模型（如 spaCy 的 CARDINAL/MONEY 标签）需要额外的模型加载和推理开销，且对非英语文本或非标准格式（如"166.32美元"混合中英文）可能需要专门适配。正则表达式 `-?\d+(?:\.\d+)?` 是纯模式匹配，零依赖、零延迟，且对数字的匹配不受语言、格式或上下文影响——"166.32"无论出现在中文、英文还是 JSON 格式中都能被准确提取。在预言机场景中，文本中的关键数值通常是阿拉伯数字形式（价格、百分比、温度值等），正则表达式足以覆盖绝大多数情况。

**这是 SemanticTruth 区别于 SenteTruth 的核心设计**：SenteTruth 完全不利用文本中的数值信息。**为什么这个信息重要？** 在预言机的文本数据中（如新闻摘要、市场分析），关键事实往往体现为具体数字——"目标价 166 美元"和"目标价 101 美元"传达截然不同的信息，但 SBERT 编码后的语义向量几乎无法区分它们（余弦相似度可达 0.97）。提取数值信息后，系统获得了一个独立于语义的验证通道：即使恶意源精心构造了语义上"看起来正常"的文本，只要其中的数字被篡改，数值信号就能将其识别出来。

### 5.4 亲和度矩阵构建

对于同一对象 $o$ 的 $n$ 条文本，构建 $n \times n$ 的亲和度矩阵 $A$：

**语义相似度：**

$$\text{sem}(i, j) = \mathbf{v}_i^\top \mathbf{v}_j \quad \in [-1, 1]$$

**数值相似度（高斯衰减）：**

对于两个数值列表 $L_i, L_j$，采用对称的高斯数值相似度。对于单向匹配：

$$\text{score}_{\text{dir}}(L_{\text{ref}}, L_{\text{cand}}) = \frac{1}{|L_{\text{ref}}|} \sum_{r \in L_{\text{ref}}} \exp\!\bigg(-\frac{1}{2}\bigg(\frac{\min_{c \in L_{\text{cand}}} |r - c| / \max(|r|, 10^{-8})}{\tau}\bigg)^2\bigg)$$

**为什么使用相对误差 $|r-c|/|r|$ 而非绝对误差 $|r-c|$？** 文本中出现的数字量纲和尺度差异极大：同一段文本可能同时包含"目标价 166.32 美元"（百位量级）和"上涨 29.29%"（十位量级）。如果使用绝对误差，则需要对不同量纲的数字设定不同的容差，这在不知道数字语义的情况下无法做到。相对误差天然归一化：无论数字是 0.5 还是 50000，2% 的偏差都被同等对待。分母中的 $\max(|r|, 10^{-8})$ 是为了防止参考值接近 0 时除零——此时相对误差的概念本身不适用，用 $10^{-8}$ 兜底使其退化为接近绝对误差的行为。

**为什么对每个参考值取 $\min_{c \in L_{\text{cand}}} |r-c|$（最近邻匹配）？** 两条文本中数字的出现顺序可能不一致（例如"上涨 29.29%，目标价 166.32 美元" vs "目标价 166.32 美元，涨幅 29.29%"），因此不能按位置一一对应。最近邻匹配对顺序不敏感：对参考列表中的每个数字，在候选列表中找到最接近的数字计算匹配度，确保相同的数字无论出现在什么位置都能被匹配到。

对称化：

$$\text{num}(i, j) = \frac{1}{2}\big(\text{score}_{\text{dir}}(L_i, L_j) + \text{score}_{\text{dir}}(L_j, L_i)\big)$$

**为什么需要对称化？** 单向匹配 $\text{score}_{\text{dir}}(L_i, L_j)$ 不满足对称性——如果 $L_i = [100, 200]$，$L_j = [100]$，则 $\text{score}_{\text{dir}}(L_i, L_j) = \frac{1}{2}(1.0 + 0) = 0.5$（$L_j$ 中找不到 200 的匹配），但 $\text{score}_{\text{dir}}(L_j, L_i) = 1.0$（$L_i$ 中有 100）。取均值后 $\text{num}(i,j) = 0.75$，合理反映了"部分匹配"的程度。对称性是亲和度矩阵的基本要求——"$i$ 和 $j$ 有多相似"应该与 "$j$ 和 $i$ 有多相似"一致。

其中 $\tau = 0.02$（2% 相对误差容限）。当两个数字完全一致时得分为 1.0；偏差 2% 时得分约 0.607；偏差远超 2% 时得分趋近 0。**为什么 $\tau = 0.02$？** 预言机中的数值数据（如价格、汇率）通常有较高的精度要求。$\tau = 0.02$ 表示 2% 的相对偏差是"可接受"与"可疑"的分界线：在 2% 以内的偏差（可能源于数据源的时间差或四舍五入）几乎不受惩罚（得分 > 0.6），超过 4% 的偏差（更可能是篡改）则得分急剧下降（< 0.14）。这个设定适合金融数据等精度敏感的场景；对于精度要求较低的场景（如天气数据），可以调大 $\tau$。

**混合亲和度：**

$$A_{i,j} = \begin{cases} \alpha \cdot \text{sem}(i,j) + (1 - \alpha) \cdot \text{num}(i,j) & \text{if } L_i \neq \emptyset \text{ or } L_j \neq \emptyset \\ \text{sem}(i,j) & \text{otherwise} \end{cases}$$

默认 $\alpha = 0.5$，即语义和数值各占一半权重。**为什么 $\alpha = 0.5$？** $\alpha$ 控制语义信号和数值信号的相对重要性。$\alpha = 0.5$ 将两者等权对待，基于以下考量：语义信号捕捉文本的整体含义是否一致（如"苹果股价上涨"vs"苹果股价下跌"），数值信号捕捉关键数字是否正确（如"166 美元"vs"101 美元"）。两类信号针对不同类型的攻击——纯语义篡改（如随机回答无关内容）被语义信号捕获，精细数值篡改（如保留语义只改数字）被数值信号捕获。等权设置不偏袒任何一方，确保两种攻击都能被检测到。

**为什么当文本不含数字时退化为纯语义比较？** 如果两条文本都不包含数字（例如纯描述性文本"今天天气晴朗，适合出行"），数值信号不存在，强行给数值分一个默认值（如 0 或 1）会引入偏差。退化为纯语义比较是最自然的 fallback——没有数值信息时，语义相似度是唯一可用的信号。条件 $L_i \neq \emptyset \text{ or } L_j \neq \emptyset$（只要任一方有数字就启用混合）确保了：如果一条文本包含数字而另一条不包含（可能是恶意源故意删除了关键数字），数值匹配得分会很低，这种差异会被捕获。

**与 SenteTruth 的对比**：SenteTruth 的 $\phi(v_i) = \frac{1}{n-1}\sum_{j \neq i} \cos(v_i, v_j)$（Eq. 2）仅使用语义相似度。SemanticTruth 在相似度中融入了数值匹配信号，使其能识别"语义相近但数值错误"的攻击——这是 SenteTruth 的盲区。

### 5.5 软投票真值选择

每条文本的投票得分：

$$\text{score}(i) = \sum_{j \neq i} A_{i,j} \cdot r_{s_j}$$

即：所有其他源对文本 $i$ 的支持度（亲和度 $\times$ 可信度）之和。选择得分最高的文本作为真值：

$$\hat{t}_o = t_{\arg\max_i \text{score}(i)}$$

**为什么得分来自其他源的加权支持，而非自身属性？** SenteTruth 使用 $D = \arg\max_i C_i \cdot \phi(v_i)$（Eq. 3），将自身可信度 $C_i$ 与自身语义相关性 $\phi(v_i)$ 相乘。这种设计存在一个安全隐患：如果一个恶意源在历史上通过提供正确答案积累了较高的 $C_i$，当它开始作恶时（提供一个与多数不同的答案），其得分 $C_i \cdot \phi(v_i)$ 仍可能因高 $C_i$ 而击败低可信度的诚实源。SemanticTruth 的设计将得分的来源从"自身属性"改为"他人支持"——一条文本的得分等于所有**其他**高可信度源对它的亲和度之和。恶意源即使自身可信度较高，如果它提供的文本与其他高可信度源的文本不一致（亲和度低），其得分仍然很低。换言之，在 SemanticTruth 中，**一条文本要当选为真值，必须获得多个独立的高可信度源的"背书"**，单个高可信度恶意源无法凭一己之力操控结果。

**为什么用求和而非取最大值或平均值？** 求和聚合使得**支持者越多、支持者可信度越高**，总分越高——这直接反映了"多数诚实源的共识"。如果用取最大值，则一个单一高可信度源的支持就足够，削弱了"多数共识"的约束；如果用平均值，则一个只有两个高可信度支持者的文本可能因平均分高而击败有五个中等可信度支持者的文本，不符合"数量也重要"的直觉。

### 5.6 数值共识构建

选出 winner 文本后，需要为 consistency 评分建立数值参考基准。从所有源提取的数值列表中，找出长度最多的组（mode length），对每个位置取**加权中位数**：

$$\text{consensus}[k] = \text{WeightedMedian}\big(\{L_i[k]\}_{i \in \mathcal{A}},\; \{r_{s_i}\}_{i \in \mathcal{A}}\big)$$

其中 $\mathcal{A}$ 是数值列表长度等于 mode length 的源集合。

**为什么按 mode length 分组？** 不同源的文本可能包含不同数量的数字——有的报告"目标价 166.32 美元，上涨 29.29%"（2 个数字），有的只报告"目标价 166 美元"（1 个数字）。为了在各位置上逐一构建共识，需要对齐各源的数值列表，这要求参与对齐的列表长度一致。取出现次数最多的长度（mode length）是因为诚实源通常对同一事件报告相似的信息粒度——如果大多数源都报告了 3 个数字，那 3 就是"正常"的信息量，报告更多或更少数字的源可能遗漏或多提取了信息。筛选出 mode length 的源集合，确保参与共识的源在信息粒度上一致，避免了长短不一的列表在逐位置对齐时的混乱。

**为什么用加权中位数而非加权平均构建共识？** 与数值通道的真值估计（Section 4.3）一致，加权中位数对离群值更鲁棒。如果恶意源恰好也有 mode length 个数字（但数值被篡改），加权中位数不会被其拉偏，而加权平均会。这保证了数值共识基准本身的可靠性——基准不准确会导致后续一致性评分的误判。

### 5.7 一致性评分

文本通道的一致性得分由语义分和数值分混合而成：

**语义分：**

$$c_i^{\text{sem}} = \text{clip}(\mathbf{v}_i^\top \mathbf{v}_{\text{winner}},\; 0,\; 1)$$

**为什么对余弦相似度做 clip 到 $[0, 1]$？** 余弦相似度的理论范围是 $[-1, 1]$，负值表示语义上相反。但一致性得分 $c_s$ 需要在 $[0, 1]$ 范围内，因为它将被用于 Beta-Bernoulli 更新（$\alpha_s += \eta \cdot c_s$，$\beta_s += \eta \cdot (1-c_s)$）。如果 $c_s < 0$，则 $\alpha$ 减少且 $\beta$ 增加超过 $\eta$，可能导致 $\alpha$ 变为负数，破坏 Beta 分布的定义。clip 到 0 意味着"语义完全相反"和"语义无关"被同等对待（都是最差的表现），这在预言机场景中合理——无论一个源的回答是"无关"还是"相反"，都说明它没有提供正确信息。

**数值分（高斯衰减 + MAD 自适应 scale，与数值通道一致）：**

对每个对齐位置 $k$：

$$\text{scale}_k = \max\big(1.4826 \times \text{MAD}_k,\; \text{std}_k,\; \epsilon_{\text{tol}}\big)$$

$$c_{i,k}^{\text{num}} = \exp\!\bigg(-\frac{1}{2}\bigg(\frac{L_i[k] - \text{consensus}[k]}{\text{scale}_k}\bigg)^2\bigg)$$

$$c_i^{\text{num}} = \frac{1}{K}\sum_{k=1}^K c_{i,k}^{\text{num}}$$

其中 $K$ 为 consensus 长度，$\text{MAD}_k$ 和 $\text{std}_k$ 由该位置所有对齐源的值计算。

**混合一致性：**

$$c_i^{\text{txt}} = \begin{cases} \alpha \cdot c_i^{\text{sem}} + (1-\alpha) \cdot c_i^{\text{num}} & \text{if } c_i^{\text{num}} \text{ exists} \\ c_i^{\text{sem}} & \text{otherwise} \end{cases}$$

**为什么一致性评分也使用与亲和度矩阵相同的 $\alpha$ 混合比例？** 亲和度矩阵中 $\alpha = 0.5$ 控制的是"投票时语义和数值各占多少权重"，这里的 $\alpha$ 控制的是"评分时语义和数值各占多少权重"。两者使用相同的 $\alpha$ 是为了保持一致性：如果投票阶段更看重数值信号（$(1-\alpha)$ 大），那么评分阶段也应该更看重数值一致性——否则一个源可能因数值篡改在投票中落败（被数值信号拉低亲和度），但在评分中却获得高分（因为评分阶段不看重数值），导致逻辑矛盾。使用同一个 $\alpha$ 确保投票和评分的标准一致。

**数值通道统一性说明**：数值通道的一致性评分（Section 4.4）使用 $\exp(-\frac{1}{2}(r/\text{scale})^2)$ 形式；文本通道中嵌入数值的评分（本节）使用完全相同的公式和 scale 计算方式。**为什么要保持这种统一性？** 两个通道都需要把"一个数值与参考值的偏差"转换为 $[0,1]$ 的一致性得分——如果数值通道用高斯衰减而文本通道用线性衰减，同样的偏差在两个通道中会产生不同的得分，导致跨通道可信度更新（Section 3.2）中两个通道的评分不可比。统一公式使得两个通道的数值一致性得分具有相同的统计含义，可以被直接平均。

## 6. 完整流程

对于每个 epoch $e$：

```
输入：数值 DataFrame (website, object, fact_numeric, batch_index)
      文本 DataFrame (website, object, fact_text, batch_index)

1. 初始化/读取所有源的 (α_s, β_s)，计算 r_s = α_s / (α_s + β_s)
2. 数值通道：
   a. 按 object 分组
   b. 门控过滤低可信度源
   c. IRLS + Tukey bisquare 估计真值
   d. 高斯衰减计算 consistency c_s^num
3. 文本通道：
   a. 按 object 分组
   b. SBERT 编码 + 数值提取
   c. 构建语义+数值混合亲和度矩阵
   d. 软投票选出 winner 文本
   e. 构建加权中位数数值共识
   f. 高斯衰减 + 语义 cosine 计算 consistency c_s^txt
4. 可信度更新：
   c_s = mean(c_s^num, c_s^txt)
   α_s += η·c_s,  β_s += η·(1 - c_s)

输出：每个 object 的真值估计，每个源的更新后可信度
```

## 7. 与现有方法的系统性对比

### 7.1 真值估计方法对比

| 方法 | 数值真值 | 文本真值 |
|------|---------|---------|
| BasicTruth | 不区分数值/文本，统一用 TF-IDF cosine 做 implication | 同左 |
| DecentTruth | 加权平均 $\hat{x} = \frac{\sum r_s x_s}{\sum r_s}$ | 不处理文本 |
| SenteTruth | 不处理数值 | $\arg\max_i C_i \cdot \phi(v_i)$（语义相关度 × 可信度） |
| SenFeedTruth | 加权平均 + 历史平滑（Eq. 2, 7） | 不处理文本 |
| **SemanticTruth** | 加权中位数 + IRLS Tukey bisquare | 语义+数值混合亲和度软投票 |

### 7.2 异常抑制机制对比

| 方法 | 机制 | 特点 |
|------|------|------|
| BasicTruth | 无 | 不考虑恶意源 |
| DecentTruth | $\kappa_s = \text{erfc}(\beta \| \Delta\epsilon \|)$ | 检测误差**变化** |
| SenteTruth | 语义相似度自然降权 | 偏离多数的文本得低分 |
| SenFeedTruth | $\Delta w > \sqrt{\epsilon}/\|S\|$ 触发重收敛 | 权重突变检测 |
| **SemanticTruth** | Tukey bisquare 降权（batch 内）+ Beta-Bernoulli 门控（跨 batch）+ 亲和度矩阵（文本） | batch 内鲁棒估计 + 跨 batch 累积过滤恶意源；文本中数值错误拉低亲和度 |

### 7.3 跨批次学习对比

| 方法 | 记忆机制 | 衰减特性 |
|------|---------|---------|
| BasicTruth | 无（每次从头迭代收敛） | 无记忆 |
| DecentTruth | EMA 平滑 $\kappa_s = \text{erfc}(\cdot)(1-\alpha) + \hat{\kappa}_s \cdot \alpha$ | 指数衰减（$\alpha$ 控制） |
| SenteTruth | $C_i$ 跨 batch 保留 | 乘法更新，无衰减上界 |
| SenFeedTruth | Gamma 先验累积（MAP 估计） | 证据越多先验越强 |
| **SemanticTruth** | Beta 分布 $(\alpha_s, \beta_s)$ 累积 | 贝叶斯更新，$\alpha+\beta$ 越大惯性越强 |

### 7.4 对"语义相近但数值错误"攻击的应对

这类攻击中，恶意源保留原始文本的语义结构，仅篡改关键数字（如将"目标价 166.32 美元"改为"目标价 101.19 美元"）。此时恶意文本与诚实文本的 SBERT cosine 相似度可高达 0.97。

| 方法 | 应对能力 | 原因 |
|------|---------|------|
| BasicTruth | 无 | TF-IDF 对数字变化不敏感 |
| DecentTruth | 不适用 | 不处理文本 |
| SenteTruth | **无法识别** | 纯语义相似度无法区分数值差异 |
| SenFeedTruth | 不适用 | 不处理文本 |
| **SemanticTruth** | **可识别** | 亲和度矩阵中数值通道 $\text{num}(i,j)$ 捕获数值差异，降低恶意文本的投票得分 |
