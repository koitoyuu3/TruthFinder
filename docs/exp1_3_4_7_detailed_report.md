## 0. 阅读本文前需要知道的几个基础概念

### 0.1 五种被对比的方法

> 注：`exp1_text/exp3_text/exp4_text/exp7` 中**只跑 3 种**（BasicTruth、SenteTruth、SemanticTruth），因为另外两种是纯数值方法。

### 0.2 两种攻击模式（出现在 outputs 文件夹名里）

- **`collude`（协同/串谋）**：被选中的恶意节点联合起来，对**同一个 object** 给出同一个错误答案，让"多数原则"被污染。
- **`numonly`（仅数值偏离）**：恶意节点只在文本里把数字改错，整段叙述其余部分照抄真值——专门考验"语义对，但数值假"这种细粒度攻击。

### 0.3 两个核心指标

- **数值实验**用 **Relative RMSE**（相对均方根误差，列名 `rmse` / `relative_rmse`，`metric_scale = relative`），值越接近 0 越好。
- **文本实验**用 **DataAccuracy（DataAcc）**，定义见 §0.4；exp1/exp3/exp7 还会附带 **Mean Hybrid Score**。

### 0.4 DataAcc 的定义（重要）

$$
\text{DataAcc}(\alpha,\tau) = \frac{1}{N}\sum_k \mathbb{1}\big[\;\alpha\cdot\text{SemSim}_k + (1-\alpha)\cdot\text{NumSim}_k \;\ge\; \tau\;\big]
$$

- `SemSim`：clean 文本与方法预测文本的 SBERT 余弦相似度
- `NumSim`：从 clean 文本抽出的数字，在预测文本中能否被找到（相对误差 ≤ 0.02）的命中率
- $\alpha$：语义/数值混合权重；exp1/exp3/exp4 使用模型默认 $\alpha=0.5$；exp7 专门扫描 $\alpha$
- $\tau$：判定阈值，**outputs 中实际只出现两个值：0.85 和 0.90**

> 在下文以及 CSV 里还会反复出现一个列叫 **`mean_hybrid_score`**，它和 DataAcc 的关系参见 §0.4.1。

#### 0.4.1 `mean_hybrid_score` 是什么

对每一个被评估的"预测单元" $k$（在文本实验里是 (batch, object) 这一对，即"在第 $b$ 个 batch 里、对第 $o$ 个题目融合出的真值预测"），先按 §0.4 的混合公式算出**单点 hybrid score**：

$$
\text{score}_k \;=\; \alpha\cdot\text{SemSim}_k \;+\; (1-\alpha)\cdot\text{NumSim}_k \quad\in[0,1]
$$

这个 $\text{score}_k$ 是一个**连续的相似度分数**：1 表示预测文本与 clean 真值在语义、数字两路都几乎一致；越靠近 0 表示越偏离真值。它**不依赖 $\tau$**——τ 只是后面把它二值化时用的判定线。

CSV 里的 `mean_hybrid_score` 就是把这一 batch 内所有预测单元的 $\text{score}_k$ 取算术平均：

$$
\text{mean\_hybrid\_score}(b) \;=\; \frac{1}{|K_b|}\sum_{k\in K_b}\text{score}_k
$$

它和同一行的 `data_accuracy` 之间是"原始分数 vs 阈值化判定"两种视角：

| 列 | 类型 | 含义 | 是否依赖 $\tau$ |
|---|---|---|---|
| `mean_hybrid_score` | 连续值 ∈ [0,1] | 该 batch 所有预测的混合相似度均值，越大越接近真值 | **否**（τ-无关） |
| `data_accuracy`     | 0/1（或 [0,1] 比例） | 该 batch 内"过线"预测的占比，等价于 $\frac{1}{|K_b|}\sum_k \mathbb{1}[\text{score}_k\ge\tau]$ | **是**（按当前 τ） |

直白点说：**`mean_hybrid_score` 是模型有多接近真值的"温度计读数"，`data_accuracy` 则是把这个读数和 $\tau$ 比较得到的"是否合格"判决**。同一 batch 哪怕 hybrid 平均分高达 0.89，只要在 $\tau=0.90$ 下没过线，`data_accuracy` 仍然会被算成 0——这正是 §2B 反复强调的"接近阈值的硬阈值悬崖"现象。

阅读 exp3 的时间序列图时尤其要注意：图的 y 轴画的就是 `mean_hybrid_score`，图里那条水平虚线就是 $\tau$（0.85 或 0.90）。曲线在虚线**上方**意味着该 batch 的 DataAcc=1，**下方**意味着 DataAcc=0；曲线大体贴在虚线附近来回穿越的方法（典型如 SenteTruth 在 Phase3）就是最容易被 τ 抖动撬动的方法。

### 0.5 数据集与污染文件如何生成

#### 0.5.1 基础数据集

实验有两套基础数据集：`data_agent-50_news-300`（50 个 agent，每个 agent 给出 300 个 batch 的新闻类回答）和 `data_agent-50_weather-300`（同规模的天气类回答）。每套数据集都包含一份"干净的文本基线"和一份"干净的纯数值基线"——前者是每个 agent 用一段自然语言描述某个客观事件（包含若干关键数字，例如某公司业绩指引、某城市未来三天的气温/风速/降水概率），后者是同一题目下纯数字形式的预测。在这两份干净数据之外，还会派生出三类污染版本：**文本协同污染**（`demo_{X}bad_collude.json`，X 取 5/10/15/20/25/30/35/40，对应 10%~80% 的恶意比例）、**仅数值污染**（`demo_{X}bad_numonly.json`，文字部分照抄真值、只把里面的数字改假）、以及**纯数值场景下的协同污染**（`num_demo_{X}bad_collude.json`，给数值实验用）。除此之外还会生成一份 `demo_div.json` —— 它是干净文本经过"诚实节点多样化"处理后的版本，用途见 0.5.3。

#### 0.5.2 污染数据是怎么造出来的（流程总述）

整个污染数据的生成可以理解为四个先后步骤：

1. **先确定真值**。从干净基线里挑一个固定 agent（实现上是 agent-1）的回答作为"标准答案文本"——它本身就是一段已经写好的、包含正确数字与正确叙述的回答。这段文本之后既不会被修改，也是后续所有污染版本伪造时的对照锚点。
2. **再让诚实节点之间不要太像**。除了 agent-1 之外的所有诚实 agent，都要给它的原文加上一段"宏观开场白"（约 45 字）和一段"风险/提醒收尾语"（约 40 字）。每个诚实 agent 拿到的开场白和收尾语是从一组 15×15 的备选库里挑出来的、**互不相同**的组合，因此每个诚实 agent 的最终文本在字面上都不一样，但所传达的事实数字和判断方向仍然与真值一致。这一步放在污染之前完成，原因见 0.5.3。
3. **再决定谁是恶意节点、谁来分配立场**。脚本固定地把 agent-1 一直到 agent-{X} 标记为这一轮的恶意节点（X 就是当前文件名里的 bad_count）。这些恶意节点不是各自独立胡编，而是先被分成若干个"攻击方向组"，每一组共享同一个造假立场——具体如何分组随 X 而变（见 0.5.4）。
4. **最后让每个恶意节点去伪造每一道题的回答**。对于每一个 (batch, 题目)，脚本会针对每个恶意节点查它属于哪个方向组，然后按这个方向组的"模板"生成一段假回答：在 `collude` 模式下，正文叙述也会朝该方向改写（例如把"业绩上调"改成"业绩下调"、把"小幅回暖"改成"明显走弱"），并把里面的数字按这个方向规定的缩放系数改大或改小；在 `numonly` 模式下，叙述照抄干净文本一字不差，只把里面的数字按方向规定的系数改掉。所有结果按 (agent, batch) 写回成一份新的 JSON，文件名编码了 bad_count 与攻击模式。

> 直白点说：每一份 `demo_{X}bad_*.json` 都是把干净基线整体复制一遍，再把前 X 个 agent 的回答替换为按既定立场伪造的假回答；剩下 50−X 个 agent 的回答保持"加了花边但事实正确"的样子。

#### 0.5.3 为什么要先把诚实节点的文本"加花边"

如果不在污染前先给诚实节点加上各不相同的开场白和收尾语，所有诚实 agent 的回答字面上几乎一致——SBERT 编码出来的句向量两两相似度会非常高（接近 0.95）。这种情况下，sentinel 类方法只要看到任何一个"和大家不一样"的回答就能 100% 锁定为恶意，实验做出来会显得鲁棒性强得离谱，但完全不像现实场景。加了花边以后，诚实节点之间的语义相似度被人为压低到 0.55~0.65 这个量级，**让"诚实"和"恶意"之间的边界变得模糊**——sentinel 方法必须真的依赖语义/数值差异去甄别，而不是简单的字面对齐；SemanticTruth 也才有真实的多簇环境去演示它的聚类能力。这一步可以理解成给整个实验"调难度"，让方法之间的差异变得可观测。

#### 0.5.4 攻击方向组（**重要**：高恶意比例下不是单一方向）

恶意节点不是无序乱写的，他们按 bad_count 被切分成若干"立场组"，每一组共享同一个造假方向：

| 恶意人数 | 比例 | 分组（每组人数） | 方向数 | 立场示例 |
|---|---|---|---|---|
| 5  | 10% | (5)                  | 1 | 全员"看空" |
| 10 | 20% | (10)                 | 1 | 全员"看空" |
| 15 | 30% | (15)                 | 1 | 全员"看空" |
| 20 | 40% | (20)                 | 1 | 全员"看空" |
| 25 | 50% | (15, 10)             | **2** | "看空" + "看多" |
| 30 | 60% | (15, 15)             | **2** | "看空" + "看多" |
| 35 | 70% | (12, 12, 11)         | **3** | "看空" + "看多" + "需求骤降" |
| 40 | 80% | (8, 8, 8, 8, 8)      | **5** | 五种相互冲突的不同立场 |

**含义讲清楚**：当总体恶意比例 ≤ 40% 时，所有恶意 agent 抱成一团，只朝一个方向造假——比如他们全部把业绩说成"下调"、把数字一律往下打到真值的 78%~88%。但是，一旦恶意比例 ≥ 50%，他们就会被人为地拆分成 2 个、3 个甚至 5 个**互相冲突的立场子团**：一部分继续看空，另一部分却看多，再有一部分鼓吹需求骤降，等等。

这样设计是有意的"攻击难度调度"，原因是：

- 如果在 ≥ 50% 时仍让所有恶意节点统一朝一个方向造假，那就成了"恶意压倒性多数"——任何只看"多数说什么"的方法都会被一票否决，结果上只能看到所有方法集体失败，**完全无法区分方法之间的优劣**。
- 切分成多个对立方向后，**没有任何一个方向能占到绝对多数**（即使是 80% 总恶意，最大的子团也只有 8/50 = 16%，比 50−40 = 10 个诚实节点还少）；这反而模拟了现实场景：网络上往往同时存在多种相互矛盾的谣言，没有哪一种谣言能压过事实本身。在这种结构下，**SemanticTruth 的"按语义聚簇"才能发挥作用**——多个方向的恶意会被自动聚成多个小簇，而真值簇仍然是最大的单一簇。这就是为什么 1B.3 / 2B.2 表里高比例下 SemanticTruth 反而还能保住 0.7~0.8 的根本原因。

#### 0.5.5 一个方向的"攻击模板"具体在做什么

每个攻击方向相当于一个完整的"造假人设"，由三件事组成：

1. **数字怎么改**。每个方向都规定了一个"对偶数下标 agent 用的缩放系数"和一个"对奇数下标 agent 用的缩放系数"，例如"看空"方向用 0.78 / 0.88，意味着属于这一组的恶意节点会把真值里的所有数字打到原来的 78%~88%——既统一朝下偏移，又不至于完全相同（避免被一眼识别为"完全一样的假数据"）。"看多"方向则相反，把数字放大到 1.18~1.28 倍。
2. **叙述里的关键词怎么换**。每个方向带一组短语替换规则：把"上调"换成"下调"、把"利好"换成"承压"、把"回暖"换成"走弱"等等，让伪造文本读起来确实像是在朝该方向论证，而不只是把数字改了。
3. **同义改写让伪造文本不雷同**。如果同一组的所有恶意节点写出完全一字不差的伪造文本，任何方法都能把它们识别成"明显的复制粘贴"。所以每个方向还配有几套"同义改写表"（比如"约为 ↔ 大约为"、"温度 ↔ 气温"），让同组内不同 agent 写出的假文本在字面上有细微差别，但语义内核一致。

`numonly` 模式只做第 1 步——数字按方向缩放；第 2、3 步全部跳过，叙述部分原封不动从干净文本复制过来。这就造出了一种特殊样本：**整段话读起来跟真值几乎一样，唯独里面的数字是错的**。这种攻击专门挑战那些只看语义相似度、对数字精确度不敏感的方法（即 1.2 / 1.4 子实验里 SenteTruth 在 30%→40% 之间出现"语义看上去对、但全员被判错"那个悬崖的成因）。

#### 1A.5 结果为什么是这样

1. **BasicTruth 最早崩**：仅 2/10 = 20% 串谋就让其 RMSE 从 0.0018 飙到 0.0133（相比无攻击高出近 100 倍），因为它本质上就是"多数原则"，当恶意节点能与诚实节点平票时，confidence 迭代会把毒预测拉成"赢家"。在 50agent 场景里只要 5/50 = 10% 串谋就直接饱和到 ~0.0197。
2. **DecentTruth / SenteTruth 在 ≤ 40% 串谋时几乎不动**（≈ 0.002 量级），但在 50% 时同样掉到 0.02 附近——这里是"裁判节点也被串谋污染"的临界点：sentinel 集合本身有限，一旦串谋者占据其中一席，加权机制就破产。
3. **SenFeedTruth 退化是线性的**：每多 1 个恶意，RMSE 大约 +0.002。它不像 sentinel 那样"全有/全无"，而是把所有节点都当反馈源，所以毒数据是平摊进去的。
4. **SemanticTruth 在数值场景下表现很怪**（在 bad=2,4 时甚至比 bad=1 还低）：因为它在数值列的实现是"先聚类再投票"，数据量小时聚类阈值容易把毒点单独成簇并丢弃；但当串谋节点足够多形成自己的簇时（25 个/50 时），它也立刻饱和。
5. **DecentTruth/SemanticTruth 在 50% 之前都明显优于 SenFeedTruth**：说明"硬截断"的鲁棒性策略（把可疑节点权重直接归零）在中等攻击强度下优于"线性削弱"。

### 1B. EXP1_TEXT（文本版，包含 4 个独立子实验）

#### 1B.1 输出位置

```
outputs/exp1_text/
├── 1.1-agent-50-news-300-80%-0.85-collude/
├── 1.2-agent-50-news-300-50%-0.9-numonly/
├── 1.3-agent-50-weather-300-80%-0.85-collude/

```

文件夹名编码方案 `<编号>-agent-<N>-<数据>-<最大恶意比例>-<DataAcc阈值>-<攻击模式>`：

| 编号 | 数据集 | 扫描范围 | DataAcc τ | 攻击 | CSV 行数 |
|---|---|---|---|---|---|
| 1.1 | news | 0% → 80% | 0.85 | collude | 9 |
| 1.2 | news | 0% → 50% | **0.90** | **numonly** | 6 |
| 1.3 | weather | 0% → 80% | 0.85 | collude | 9 |
| 1.4 | weather | 0% → 80% | **0.90** | **numonly** | 9（**额外保留 raw `_score` 列**） |

#### 1B.2 CSV 字段

5. **weather > news**：对比 1.1 vs 1.3、1.2 vs 1.4，weather 列在同样攻击强度下普遍更稳。原因是 weather 描述模板化程度高、数字更结构化，NumSim 分量更可靠。

#### 1C.3 与 agent-50 的对照解读

1. **整体趋势完全一致，但 SenteTruth 的"悬崖"提前了**。在 agent-50 跑的 1.1/1.3 上，SenteTruth 的崩塌点出现在 50%→60%，而 llama 复跑里悬崖前移到 30%→40%（1.1：1.000 → 0.143；1.3：0.993 → 0.693）。原因是 llama 生成的诚实文本本身风格更松散、数字结构化程度低于 GPT-agent 的回答，sentinel 子集对"诚实参考"的辨识能力下降，于是更早被串谋者覆盖。
2. **LASO(Ours) 在 ≤ 50% 串谋时依然显著领先**，但在高比例下降速比 agent-50 快。例如 1.1：60%→70%→80% 在 agent-50 上是 0.983 → 0.817 → 0.733（仍可用），llama 对应位置则是 0.717 → 0.240 → 0.240——SBERT 聚类在 70%/80% 比例下被 llama 自身的文本风格扰动击穿。这恰恰说明 LASO(Ours) 的稳健性同时依赖"真值簇足够紧凑"与"恶意簇能被一致地推开"，而 llama 写出来的诚实文本在语义空间内分布更宽，给恶意分簇提供了可乘之机。
3. **numonly 攻击下 llama 的 SenteTruth 崩得更深**。1.2 在 40% 处 SenteTruth 直接跌到 0.083，1.4 在 50% 处跌到 0.013。对比 agent-50（1.2 ≈ 0.077；1.4 ≈ 0.120），llama 版几乎完全失能——因为 numonly 攻击保留叙述、只改数字，sentinel 看到的语义相似度仍然很高，而 llama 对数字的精确刻画本身就更弱（自然语言里的数字在 llama 输出里更易抖动），二者叠加导致 sentinel 完全识别不出毒节点。
4. **BasicTruth 的"地板"被抬高**。1.3-llama 里 BasicTruth 跨整段恶意比例都稳在 0.66 附近（远高于 agent-50 1.3 的 0.27~0.45），看上去"反而更稳"。这其实是 llama 对 weather 数字的回答比 GPT-agent 更模板化（每个 batch 的数字更接近预设区间均值），多数原则在数值高度集中时反而能稳住一个固定值——但这个值并不是真值，只是"恰好不偏离 τ=0.85 阈值的诚实子集占比"。从 LASO(Ours) 在同一行 0.99 的对照可以看出，BasicTruth 的"高地板"是评估假象，并非真的鲁棒。
5. **结论**：把基模型从 GPT-agent 换成 llama 之后，三种方法的相对排序不变（LASO(Ours) > SenteTruth > BasicTruth），但所有"机制临界点"都被推向更低的恶意比例。这说明 §1B 中观察到的 sentinel 悬崖、SemanticTruth 软退化、BasicTruth 多数失效都不是 GPT-agent 特有现象，而是方法本身的属性；同时也暴露了 LASO(Ours) 对底层文本生成质量的隐式依赖——基模型越弱，"高比例下仍可用"的安全裕度越窄。

**结果为什么是这样**（建议同时对照 §0.4.1 中"曲线 vs τ 虚线"的判读规则）

1. **τ 从 0.85 → 0.90 把 SenteTruth 的悬崖前移了一个阶段**。τ=0.85 下 SenteTruth 直到 Phase3（60%）才出现明显下降；τ=0.90 下 SenteTruth 在 Phase2（40%）就被打回 0.36（news）/在 Phase3 跌到 0.49（weather）。在图上能直接看出来：SenteTruth 的 hybrid 曲线在 Phase2/Phase3 大量贴着 0.90 来回穿越，τ 抬高 0.05 就把这一整片样本翻转成 DataAcc=0。
2. **BasicTruth 在 Phase1 就被 τ=0.90 直接打死**。news/weather 的 Phase1 DataAcc 分别只剩 0.16/0.02——比 τ=0.85 时（news 0.26、weather 0.62）下降一个数量级。在图上对应的现象：BasicTruth 的 hybrid 曲线从 Phase1 起就已大量跌到 0.4–0.85 之间，原本在 τ=0.85 下还能"擦线过"的样本，绝大多数其实都落在 0.85~0.90 这窄带里——一旦门槛抬到 0.90 全部翻车。
3. **LASO(Ours) 是唯一在 τ=0.90 下仍保持高水平的方法**（news/weather 最差 Phase 仍有 0.851/0.634）。它的 hybrid 曲线大部分时间贴在 0.95 上方，τ=0.90 这条线几乎不会切到它；只有 weather/Phase3（60% 串谋被切成 2 个对立立场）会出现少量样本掉到 0.85 附近，对应 DataAcc 从 1.000 滑到 0.634。
4. **τ=0.85 vs τ=0.90 的对比再次回到 exp7 的动机**：评估端 τ 仅从 0.85 抬到 0.90，方法之间的相对差距就从"SenteTruth 略弱于 LASO"放大到"SenteTruth 与 BasicTruth 几乎同档、远低于 LASO"。这就是为什么需要在 exp7 系统性扫描 α/τ 而不能只看一个固定切片。

#### 3A.3 解读（按方法逐条展开）

**(1) BasicTruth — 已经饱和，扩大网络毫无帮助**

RMSE 在 N=15 和 N=50 之间纹丝不动，全部停在 0.0197 这条饱和线上。这条线本身就是 exp1_numeric 中"BasicTruth 在 ≥ 10% 串谋下的最差表现值"，意味着它**不是被 5 个恶意节点稍微影响**，而是直接被这 5 个串谋者"打死"了。原因在 BasicTruth 的工作机制：它是经典 TruthFinder，本质上是一个"反复加权投票 + 不断更新置信度"的迭代过程。一旦串谋节点统一给出同一个错误答案，这个答案就会形成一个"内部高度一致的小阵营"——即便诚实节点在另一边人数更多，但他们之间的预测有自然的微小波动（正态噪声），相互之间的"互相印证"程度反而不如那 5 个齐心协力的恶意节点强。结果是**毒答案的 confidence 滚雪球反超**，而 N 增大只是给"诚实人群"添了几个数值差不多的噪声样本，并不能动摇毒答案那个超高的 confidence。所以这条曲线作为一条平坦的"上限"，完全证实了 BasicTruth 在协同攻击下与 N 无关。

**(2) DecentTruth — 已经把毒节点剔除干净，与 N 弱相关**

RMSE 长期稳定在 0.0020 附近，仅在 N=30 偶尔跳到 0.0022、N=50 偶尔降到 0.0016，整体波动 < 0.0006。它的去中心化反馈共识机制核心是"互相评分"：每个节点根据"与其他节点预测差距是否过大"动态调整自己的权重。5 个串谋者由于答案完全一致、却与诚实节点全部不同，他们获得的"被信任度"会被反馈循环迅速压到接近零，**几乎从决策中被剔除**。一旦剔除完成，剩下的 N−5 个诚实节点投票就和"无攻击"场景几乎等价——所以 N 怎么增大对 RMSE 几乎没有影响。N=50 略低于其他点的原因是诚实样本数变多以后，正常预测的方差被进一步平均，并不是机制层面的改变。

**(3) SenteTruth — 只信裁判节点，5 个毒人撼动不了**

RMSE 同样平在 0.0020 这一档（最大波动到 N=40 的 0.0018），与 DecentTruth 几乎一致。它依靠固定的"sentinel 裁判节点"来给所有人打分，本轮实验里 5 个恶意节点恰好都没落进 sentinel 子集（exp4 设定中 bad agent 是固定的前 5 个 agent，sentinel 选取规则避开了它们），所以 sentinel 看到的"参考答案"全部干净，毒节点的权重直接被打成边缘权重。**N 的变化只改变了诚实方的人数，没有改变 sentinel 子集的纯净度**，因此 SenteTruth 的表现也几乎不动。注意这条结论只在"恶意没有侵入 sentinel"的前提下成立——一旦 sentinel 被串谋污染，SenteTruth 就会出现 exp1 里那种悬崖式崩溃，但本实验固定 5 个恶意者的设定刚好绕开了这个临界点。

**(4) SenFeedTruth — 唯一随 N 单调改善的方法**

RMSE 从 N=15 的 0.0067 一路平滑下降到 N=50 的 0.0020，大约缩小到原来的 1/3，是 5 种方法中**唯一对 N 高度敏感**的。它的机制是"sentinel 给定基线 + 把所有非 sentinel 节点的反馈做线性加权融合"——不像 DecentTruth/SenteTruth 那样把可疑节点权重直接归零，而是把所有人都纳入加权平均，只是按可信度调比例。在 N=15 时，5 个毒节点占整个反馈源池的 1/3，即便每个被压低权重，叠加起来仍能拉偏整体均值；当 N 增大到 50 时，毒节点的占比降到 1/10，被同样规则削权后，他们对加权和的贡献被进一步稀释。**这条曲线是教科书式的"线性融合方法靠节点数量稀释毒源"的证据**，也告诉我们：当系统规模可以做大时，SenFeedTruth 这类"软削权"方案的代价是可以接受的。

**(5) SemanticTruth — 表现最好，但出现规则的"小-大"锯齿**

RMSE 全程在 0.0011 ~ 0.0019 之间，是 5 种方法中**误差最低的**——比 DecentTruth 和 SenteTruth 又低一档。但 8 个 N 值上能明显看到一个"小-大-小-大"的锯齿（N=15:0.0011 → N=20:0.0019 → N=25:0.0013 → N=30:0.0019 …）。要理解这个锯齿，先要明白 SemanticTruth 在数值场景下的两步走：

- **第一步：聚类**。把所有 agent 的数值预测两两比对，凡是相对差 ≤ 阈值的就放进同一个簇里。
- **第二步：在最大簇里做加权多数**。固定 5 个恶意节点因为答案完全一致，永远会**抱成一个 5 人毒簇**；剩下 N−5 个诚实节点的预测则带有自然的正态噪声，理论上落在一个紧凑的诚实区间内。

锯齿产生的关键是：**这 N−5 个诚实节点能不能被聚成一个完整的大簇**，取决于他们的数值分布刚好落在阈值带宽里、还是有一两个"分布末端的样本"刚好跨出去。

- 当 N=15、25、35、45（诚实节点数 = 10、20、30、40）时，诚实节点的数值分布恰好能稳稳地塞在一个簇里——最大簇就是这一整片 honest 节点，与毒簇大小是 (10, 5)、(20, 5)、(30, 5)、(40, 5)，**多数票完全由所有诚实节点投出**，平均效果最好，RMSE ≈ 0.0011。
- 当 N=20、30、40、50（诚实节点数 = 15、25、35、45）时，诚实节点中刚好有一两个落在分布末端、跨过了阈值边界，**被切到隔壁形成一个小副簇**——例如 honest 簇被切成 (8, 7)，加上毒簇就是 (8, 7, 5)。最大簇仍是诚实方的 8 人簇，**最终答案不会出错**，但是参与最终加权多数的样本数从原本的 15 个缩到 8 个，平均掉的噪声更少，RMSE 升到 0.0019。

所以这个锯齿**不是"机制偶尔走偏导致的性能崩坏"**，而是**"当诚实节点数恰好能整装入簇时方差小一些、否则方差大一些"** 的离散粒度效应。它的振幅只有 0.0008（对应相对误差 < 0.1%），完全不影响 SemanticTruth 在所有 N 上都全面优于其他四种方法的判断。把它理解为"聚类粒度的离散噪声"即可。

## 4. EXP7 — α（语义/数值混合权重）敏感度扫描

### 4.1 输出位置

```
outputs/exp7_alpha_sensitivity/
├── results.csv                       (297 行)
├── alpha_sensitivity_by_method.png
└── alpha_sensitivity_summary.png
```

### 4.2 实验目的

分析混合评估指标 DataAcc 中"语义—数值混合权重 $\alpha$"的敏感度——即把 §0.4 中评估端的 $\alpha$ 从 0 一路扫到 1，看不同方法的 DataAcc 排名是否会随评估口径变化而翻盘。

$$
\text{DataAcc}(\alpha) = \frac{1}{N}\sum_k \mathbb{1}\big[\;\alpha\cdot\text{SemSim}_k \;+\; (1-\alpha)\cdot\text{NumSim}_k \;\geq\; 0.85\;\big]
$$

- $\alpha = 0.0$ → 纯数值匹配
- $\alpha = 1.0$ → 纯语义匹配
- $\alpha = 0.5$ → 当前系统默认（语义/数值各半）

### 4.3 实验设置

| 项目 | 值 |
|---|---|
| 数据集 | `data_agent-50_news-300`（50 agents × 300 batch） |
| 扫描变量 | $\alpha \in \{0.0, 0.1, 0.2, \ldots, 1.0\}$（**11 个**点） |
| 恶意节点数 | 0, 5, 10, 15, 20, 25, 30, 35, 40（**9 个**点；对应 0%~80%；切分组数见 §0.5.4） |
| 对比方法 | BasicTruth / SenteTruth / SemanticTruth（3 个文本方法） |
| 评估阈值 $\tau$ | **固定 0.85** |
| 模型内部 $\alpha$ | 固定 0.5（**仅扫描评估端**的混合权重，模型本身不变） |
| 总行数 | 3 × 9 × 11 = **297** |

### 4.4 实验流程

```
对每个 bad_count ∈ {0, 5, 10, ..., 40}:
  1. 加载 clean 数据 (demo.json) 与 noisy 数据 (demo_{bad_count}bad_collude.json)
  2. 对每个方法（SenteTruth / BasicTruth / SemanticTruth）:
     a. 在 clean 数据上跑一遍，得到 clean_preds: Dict[(batch, object), str]
     b. 在 noisy 数据上跑一遍，得到 noisy_preds: Dict[(batch, object), str]
  3. 一次性预计算两组分数（关键优化：SBERT 编码只跑 1 次）：
     - sem_scores  = SBERT cosine(clean_preds, noisy_preds)
     - num_scores  = 数字抽取匹配率（相对误差 ≤ 0.02）
  4. 对每个 alpha ∈ {0.0, 0.1, ..., 1.0}:
     - combined = alpha * sem_scores + (1 - alpha) * num_scores
     - DataAcc  = mean(combined ≥ 0.85)
```

> **效率说明**：每个 (method, bad_count) 只调用 1 次 SBERT 编码，alpha 扫描阶段只是"加权 + 阈值化"的廉价算术，因此 11 个 α 点几乎不增加耗时。

### 4.5 核心指标的定义

**SemSim（语义相似度）** —— 用 `paraphrase-multilingual-MiniLM-L12-v2` 把 clean / noisy 两段文本编码为向量，做归一化点积：

$$
\text{SemSim}(x, y) = \frac{\text{SBERT}(x)\cdot \text{SBERT}(y)}{\lVert\text{SBERT}(x)\rVert \cdot \lVert\text{SBERT}(y)\rVert}
$$

若 SBERT 不可用，退化为 char-ngram TF-IDF 余弦相似度。

**NumSim（数值匹配率）** —— 把 clean 文本里的所有数字作为 reference，对每个 reference 数字 $r$ 检查 noisy 文本里是否存在 candidate 数字 $c$ 满足 $\frac{|r-c|}{\max(|r|, 10^{-8})} \le 0.02$，最后用命中率：

$$
\text{NumSim}(x, y) = \frac{\#\{r\in\text{nums}(x): \exists c\in\text{nums}(y),\, |r-c|/\max(|r|,10^{-8})\le 0.02\}}{|\text{nums}(x)|}
$$

若 clean 文本里根本没有数字，则该样本不参与 NumSim，DataAcc 退化为纯语义评估。

**混合公式**

$$
\text{score}_k = \begin{cases}
\alpha\cdot \text{SemSim}_k + (1-\alpha)\cdot \text{NumSim}_k & \text{NumSim}_k \ne \text{None} \\
\text{SemSim}_k & \text{otherwise}
\end{cases}
$$

$$
\text{DataAcc}(\alpha) = \frac{1}{N}\sum_k \mathbb{1}[\text{score}_k \geq 0.90]
$$

### 4.9 解读

1. **SemanticTruth 是唯一对 α 几乎不敏感的方法**：它的均值曲线在 α=0~1 整段都是 0.81~0.83，说明它在语义和数值两路都已经把毒预测剔除，加权方式不重要。
2. **BasicTruth 强烈偏好 α=1.0**（纯语义评估时分数最高）。原因不是它"语义模型好"，而是它在纯语义视角下的"错"经常体现为数值偏差（数字写错），把数值权重去掉就把其错误掩盖了。所以 α=1.0 时 BasicTruth 的高分**实际上是一个评估假象**。
3. **SenteTruth 的最佳 α 跟着 bad 数变**：低攻击（5~15）下偏好 α=0.5（语义+数值兼顾最稳），高攻击（≥20）下偏好 α=1.0（数值通道被串谋污染太严重，反而要看语义）。这个分水岭与 exp1_text/1.2 中 SenteTruth 在 30%→40% 的悬崖完全一致。
4. **当前系统默认 α=0.5 是合理但保守的**：
   - SemanticTruth 在 α=0.6 处略优于 0.5，但差距 < 0.005；
   - SenteTruth 在低攻击下 α=0.5 是最优；高攻击下 α=1.0 才最优。但工程上不可能动态调 α，故 0.5 是 trade-off 后的可接受值。
5. **bad=0 时所有方法在所有 α 下都拿满分**，符合直觉（无攻击没有什么需要"权衡"的）。
